# movehome 需求与技术方案（草案 v0.1）

> 面向旅游博主的个人网盘 + 足迹地图。素材存 COS，按"去过的县"点亮地图。

## 1. 已确定的技术选型

| 层 | 选型 |
|---|---|
| 前端 | React + Tailwind + Arco Design，部署到腾讯 Makers，域名 `convenience.top` |
| 后端 | Node.js 20（Lighthouse 上海，`api.convenience.top`），建议 Fastify 或 NestJS |
| 数据库 | 服务器现有 MongoDB 8.0（新建独立库 + 独立用户，开启认证） |
| 存储 | 腾讯云 COS，桶 `test-cos-1312827847`，地域 `ap-chengdu`，私有读写，根前缀 `movehome/` |
| 视频/图片处理 | COS 数据万象（CI）：转码、截帧、缩略图 |
| 地图 | 腾讯地图 JavaScript API GL，县级 GeoJSON 多边形点亮 |
| 第一版范围 | 仅网页；仅国内；不做多租户计费，但账号系统完整 |

## 2. 总体架构

```
浏览器 (convenience.top, Makers)
  │  ① 登录/元数据/业务       ② 直传、直读（临时凭证 / 签名 URL）
  ▼                           ▼
api.convenience.top (nginx → Node)      腾讯云 COS (ap-chengdu) + 数据万象
  │                                      ▲
  ▼                                      │ ③ 提交转码/截帧任务
MongoDB（本机）──────────────────────────┘
```

设计原则：
- **文件字节不经过后端**。上传、下载、播放全部浏览器直连 COS，后端只签发凭证和记录元数据。服务器只有 2 核 / 1.9 GB，必须这样。
- **重活交给 COS 数据万象**，后端不跑 ffmpeg。
- **GPS 解析放在浏览器**（上传前读取），减轻服务器压力。

## 3. 功能清单与优先级

### P0（MVP）
1. **账号**：注册、登录、退出、修改密码、找回密码（邮件）。
2. **文件管理**：文件夹树、上传（分片、断点续传、队列）、重命名、移动、删除到回收站、搜索。
3. **预览**：图片、视频（HLS 预览流）、音频。
4. **位置解析**：图片 EXIF GPS；视频同名 `.SRT` 的逐帧坐标；解析不到的支持手动指定。
5. **足迹地图第一版**：仅本人已定位素材点位，点位可回到该素材的私有预览；未定位素材明确提示，不猜测坐标。密集点位聚合按实际规模决定。

### 地图下一步（不在第一版点位地图）
- **县级点亮**：先核实可靠县界数据来源/许可及 WGS-84 与底图坐标转换，再按素材位置判定所属县、点亮并统计（县/市/省）；地区详情依赖此阶段。

### P1
7. **旅行（Trip）**：按时间与位置自动归并素材，可手动调整，带封面和标题。
8. **轨迹**：导入 GPX/KML，从 SRT 提取飞行轨迹，地图上画线并统计里程。
9. **分享**：文件/文件夹继续支持现有公开分享规则；增加把公开分享链接绘制为二维码并下载，扫码与打开原链接适用相同的提取码、有效期和撤销规则。笔记分享为纯文本只读，不套用文件下载额度。
10. **随手记**：电脑登录后保存私有纯文本笔记；手机免登录扫码，显示六位配对码，电脑核对并确认后短时只读该条笔记；另可显式创建公开分享，将同一公开链接绘制为二维码。两种二维码的授权完全独立。
11. **足迹海报**：生成点亮地图图片。
11. **手动打卡**：不依赖素材的地点记录。

### P2
12. 时间轴回放（足迹按时间逐步点亮）。
13. 素材状态标记（待剪辑/已剪辑/已发布）、评分、标签。
14. AI 标签与语义搜索。
15. 格子迷雾（战争迷雾）点亮模式。
16. 桌面端或 SD 卡自动同步。

### 暂不做
多博主运营后台、收费与配额扣费（仅预留字段）。

## 4. 关键方案

### 4.1 上传
- 后端签发约 30 分钟的 STS 临时凭证，权限限定到服务端生成的单个对象 Key，仅允许简单/分块上传相关操作；浏览器不能选择 bucket、用户目录或对象 Key。
- 浏览器通过 COS JS SDK 直传 COS，支持分块上传；文件名、大小、MIME 和目标文件夹先向 `POST /uploads/credentials` 申请上传会话。
- `POST /uploads/complete` 只接收 `uploadId`；后端按会话中绑定的用户、对象 Key 和期望大小执行 HeadObject，验证对象存在且大小一致后才幂等创建文件节点，不信任客户端传来的 Key 或完成时自报大小。
- 单文件大小受 COS 单对象上限约束（当前 API 上限 5 TB）；配额尚未启用。上传哈希/秒传暂不实现，待哈希算法、去重范围及校验规则明确后再单独定义。
- COS 桶需配置 CORS：允许实际前端来源（当前 Lighthouse `/app/` 为 `https://api.convenience.top`，本地开发为 `http://127.0.0.1:5173`），开放分块上传所需的方法和头（含 `ETag`）；当前 `https://api.convenience.top` 对 COS 的 PUT 预检返回 403，桶规则补齐前该入口不能浏览器直传。服务端 COS 子账号需具备 HeadObject 读取权限及 STS 临时凭证签发权限。

### 4.2 播放与下载
- 私有桶，访问一律使用**短时效签名 URL**（后端签发，建议 10–60 分钟）。
- 视频上传完成后，后端向数据万象提交转码任务，产出 720p HLS 和封面，原片保留。
- 转码状态：`pending → processing → done / failed`，前端轮询或后端回调更新。

### 4.3 位置解析与县级判定
- **坐标系**：自动与手动位置仍只保存 WGS-84；第一版地图接口由服务端调用腾讯官方 WebService 将本人点位临时转成腾讯底图的 GCJ-02 坐标，不回写节点。县界数据上线前需核实其数据坐标系、审图与许可，再决定是否需要双坐标保存及县级归属算法。
- **县界数据**：使用县级行政区划 GeoJSON（约 2800 个区县）。需注意数据来源的许可与审图号要求，**上线前必须核实**。
- **判定**：县界导入 MongoDB，建 `2dsphere` 索引，用 `$geoIntersects` 判断点所属县，结果写入素材的 `regionCode`。
- **前端渲染**：县界原始精度很大，需要做简化，并按省份懒加载，不能一次下发全国。
- **统计**：点亮的县集合 → 汇总到市、省。
- 边界附近、海岛、境外坐标需要兜底：判定不到县时记为"未归属"，允许用户手动指定。

### 4.4 账号与安全
- 注册登录：邮箱 + 密码；密码用 argon2id 哈希。
- 会话：短期 access token（约 15 分钟）+ 可轮换 refresh token，放 `httpOnly; Secure; SameSite` Cookie。
- 前端 `convenience.top` 与 API `api.convenience.top` 同属一个站点，Cookie 可设置在父域，需明确 CORS 白名单与 CSRF 防护。
- 所有数据带 `userId`，每个接口强制归属校验；分享链接只暴露只读签名 URL。
- 登录接口限流，防暴力破解；预留 `role`、`quota`、`status` 字段。
- 密钥（COS SecretId/Key、腾讯地图后端 Key、JWT 密钥）只放服务器环境变量。
- COS 使用**子账号 + 最小权限**，仅允许操作该桶的 `movehome/*`，禁止使用主账号密钥。

### 4.5 COS 目录约定
```
movehome/
  users/{userId}/
    originals/{yyyy}/{mm}/{fileId}.{ext}   原始文件
    previews/{fileId}/index.m3u8 ...        HLS 预览
    thumbs/{fileId}.jpg                     缩略图/封面
    tracks/{fileId}.json                    解析后的轨迹
  shares/                                    预留
```
文件名使用 `fileId`，不直接用原始文件名，避免特殊字符与冲突；原始名存在数据库里。

### 4.6 随手记与两类二维码
- **私有笔记**：标题和纯文本正文保存在账号名下的 MongoDB 集合，不伪装成 COS 文件；列表、编辑、删除均需登录并按所有者校验。前端以纯文本展示，禁止把正文当 HTML 渲染。
- **发送到我的手机**：电脑登录后针对某一条笔记创建短时配对会话，二维码携带一次性加入密钥而不包含正文或账号 Cookie；手机扫码后展示六位码，由电脑核对并确认。未获批准不返回正文；批准时冻结本次手机读取的笔记内容快照，此后仅这台设备凭会话令牌在有效期内只读该版本，电脑可撤销，笔记删除则读取失效。设备令牌不等于账号登录态，更不能复用扫码上传的令牌。
- **公开分享**：必须由所有者显式创建。笔记发布时固定正文快照，后续私有编辑不自动泄露新内容；取消分享、到期或笔记删除后不得继续公开读取。公开链接与文件分享共用公开用户名和自定义路径；笔记可选最多阅读次数，按成功领取正文的请求原子计数，页面刷新再次领取也会消耗一次，不等于独立访客数。笔记是可复制的文本，不承诺“禁下载”可以防止保存/截屏。
- **分享二维码**：笔记与文件/文件夹都可以把公开 URL 绘制成二维码并下载；二维码不包含正文、提取码、签名文件 URL 或会话令牌。修改公开路径会使旧二维码失效；已传播的二维码图片无法收回，撤销和到期则由服务端在访问时阻断。配对取笔记二维码与公开分享二维码必须明确区分。

### 足迹地图第一版 API 契约（本地实现，未部署）

- `GET /map/points?offset=0&limit=50`：要求登录，仅列当前用户未删除、`ready` 状态、MIME 为图片/视频（或 MIME 缺省为 `application/octet-stream` 且文件名以 JPEG/JPG/MP4/MOV 结尾）、且 `mediaLocation` 中 WGS-84 纬度/经度均为有效数字并处于合法范围的文件。按 `uploadedAt`、`_id` 倒序稳定分页，返回 `{items,total,offset,limit}`；每项仅包含 `id,parentId,name,mime,size,uploadedAt,location:{latitude,longitude,placeName,source}`。`id` 可用于跳转本人 `/preview/:nodeId`，预览文件仍按需调用现有 `GET /nodes/:id/url?purpose=preview` 签发短期私有链接；地图接口不批量签 URL、不返回 COS Key，也不提供公开点位。
- `GET /map/unlocated?offset=0&limit=50`：同一认证与文件范围，列出缺失、为空或坐标不完整/越界的图片和视频；返回相同分页外壳，条目不含 `location`，`total` 为待标记素材总数。音频、其他类型、未就绪、回收站及他人素材均不计入两类列表；没有坐标的素材不会生成地图点位，位置可从预览页现有 `PATCH /nodes/:id/location` 手动补充。
- 两接口 `offset` 默认为 `0`、最大 `100000`；`limit` 默认为 `50`、范围 `1–100`；不接受额外参数，非法参数返回 `400 INVALID_INPUT`，未登录返回 `401`。响应均设置 `Cache-Control: private, no-store`。`total` 是服务端匹配数量，并非当页数量；前端需继续分页直至获取所需点位，不能将首批 50 条当作全部。首版不提供地图聚类、县级点亮或省市县统计。配置服务端 `TENCENT_MAP_SERVER_KEY` 后，`/map/points` 调用固定腾讯 WebService 坐标转换接口（GPS `type=1`，单批 `locations` 不超过 2048 字符）为每项附加 GCJ-02 `mapLocation:{latitude,longitude}`，`mapStatus:'ready'`；未配置返回 `not_configured`、转换失败返回 `unavailable`，均保留原始 WGS-84 供列表显示但不在底图绘制。前端另需公开且绑定网页域名的 `VITE_TENCENT_MAP_KEY` 才加载腾讯 JS GL SDK，浏览器不接触服务端转换 Key。

### 上传 API 契约

- 两个接口均要求登录；上传用户只取自认证会话，节点父级必须是该用户的活动文件夹。
- `POST /uploads/credentials` 请求体为 `{ name, size, mime?, parentId? }`，名称最长 255 字符，大小为 0–5 TB（5,000,000,000,000 字节），`parentId` 缺省或 `null` 表示根目录。服务器生成 `uploadId`、`fileId` 和 COS Key；客户端不得提交 bucket 或 Key。
- 成功返回 `{ uploadId, fileId, bucket, region, key, credentials, expiresAt }`。返回的 STS 凭证有效约 30 分钟，只能对这一个对象执行上传/分块上传相关操作；响应设为 `Cache-Control: private, no-store`。长期 COS 密钥不返回给客户端。
- `POST /uploads/complete` 请求体为 `{ uploadId, location?: { latitude:number, longitude:number, source:'exif'|'srt' } }`。后端按认证用户的会话记录执行 HeadObject，要求对象存在且实际 `Content-Length` 与申请时的 `size` 相同，父目录仍有效后才创建 `type=file` 节点。位置字段仅能由 JPEG/JPG 的 EXIF 或 MP4/MOV 视频的 SRT 提交，经严格字段、坐标范围（纬度 −90～90、经度 −180～180）及来源/文件格式校验；不接受 `manual` 作为自动来源，不接收文件字节或客户端自报的对象 Key。无坐标时省略 `location`，照常入库。只在首次创建节点时写入自动位置；重复完成返回同一节点且 `idempotent:true`，不会更新或覆盖已有手动位置；验证失败为 `400 INVALID_INPUT`，认证/归属失败为 `401`/`404`。
- 上传会话最长保留 24 小时，`upload_sessions.expiresAt` 由 TTL 索引清理；该 TTL 只清理 Mongo 会话，不会清理 COS 对象或未完成分块。上线前仍需配置 COS 未完成分块回收，并规划过期上传对象的孤儿清理。STS 到期早于会话到期。父目录在上传期间被删除时，完成登记返回冲突，不会写入节点。
- 节点的 `uploadedAt` 记录入库时间，与 `updatedAt` 分离，避免后续改名/移动影响“最近添加”排序。客户端 MIME 仅作为声明元数据；对象大小由 COS 校验。哈希校验、秒传和配额扣减尚未实现。

### 电脑授权手机扫码上传（本地实现，未部署）

- 电脑登录后 `POST /phone-uploads` 严格接收 `{parentId:string|null}`，仅可绑定自己的活动文件夹，返回 `{id,secret,joinUntil}`；QR URL 为同站点 `/phone-upload/:id#secret`，二维码原始密钥只返回创建者且数据库仅存 SHA-256 哈希，不含 Cookie、COS 密钥。扫码加入有效期 5 分钟且仅允许一部设备（相同设备令牌的网络重试可恢复）；前端将片段从地址栏移除，并临时保留在本标签页直至完成配对。
- 手机无须登录，先在本标签页生成并保存设备令牌；`POST /phone-uploads/:id/join` 严格接收 `{secret,deviceToken}` 并原子占用二维码（同设备可重试），返回 `{deviceToken,code,status:'awaiting'}`；电脑凭登录态 `GET /phone-uploads/:id` 查询 `{status,code,approvedUntil,completedCount,recentFiles}`，核对六位配对码后 `POST /phone-uploads/:id/approve` 才发放 1 小时授权；`POST /phone-uploads/:id/revoke` 可结束授权。手机携带 `Authorization: Bearer <deviceToken>` 查询 `GET /phone-uploads/:id/status`，只有批准后返回目录名，手机不持有电脑账号 Cookie。
- 手机在批准后 `POST /phone-uploads/:id/credentials` 严格接收 `{name,size,mime?}`，**不接受 parentId/bucket/key**，后端固定所有者和目标目录、每会话至多签发 100 次、每文件至多 5 GB，签单文件约 30 分钟 STS；`POST /phone-uploads/:id/complete` 严格接收 `{uploadId,location?}`，只能完成本扫码会话创建的上传任务，复用普通完成接口的 COS 大小与目录二次校验及幂等入库。电脑端每 2.5 秒读取已完成数和最近 10 个文件名，可打开目标目录核对；`GET /phone-uploads/active?parentId=...` 可在电脑刷新后恢复同目录活动会话及撤销入口，同目录未过期会话不重复创建；并非直接写入电脑本地磁盘。
- 设备令牌仅在手机本标签页临时保存、服务端仅存哈希；扫码记录 24 小时 TTL 清理。批准到期后不得再申请新 STS，已签的上传任务可在扫码记录未过期且电脑未撤销时继续登记；撤销会阻止后续登记，但不能立刻回收已签发到 COS 的临时凭证。正式可用前需在 COS 桶 CORS 中允许实际上传页 Origin，并完成真实手机到电脑端的授权与直传验收。

### 随手记与手机读取 API 契约（本地实现，未部署）

- 私有笔记（登录）：`POST /notes` 接受 `{title,content}`，标题 1–80 字符、正文 1–10000 字符，均按纯文本保存；`GET /notes?offset=0` 返回 `{items,total,offset}`，列表不含正文，按更新时间倒序、单页最多 50；`GET /notes/:id` 返回正文，`PATCH /notes/:id` 修改标题或正文，`DELETE /notes/:id` 软删除。所有查询/修改均限定当前登录用户且未删除的笔记；错误 ID 和越权不暴露他人内容。响应不缓存，前端不能把正文插为 HTML。
- 电脑发起（登录）：`POST /note-pairs` 只收 `{noteId}`，确认笔记属于本人后返回 `{id,secret,joinUntil}`；手机二维码地址使用主站 `/phone-note/:id#secret`，加入密钥只在生成时返回、服务端仅保存哈希，不携带登录 Cookie 或正文。加入窗口 5 分钟；`GET /note-pairs/active?noteId=...` 返回 `{id:string|null}` 以便刷新后恢复授权管理，不重发二维码密钥；电脑 `GET /note-pairs/:id` 查询状态与手机显示的六位核对码，核对无误后 `POST /note-pairs/:id/approve` 冻结该笔记当刻标题与正文、批准十分钟只读，或 `POST /note-pairs/:id/revoke` 立即撤销。
- 手机无需登录：扫码页面生成独立设备令牌，调用 `POST /note-pairs/:id/join`（`{secret,deviceToken}`）获取配对码，显示给电脑用户核对；获批前只可凭 `Authorization: Bearer <deviceToken>` 查询 `GET /note-pairs/:id/status`（不会重复返回六位码），获批后同令牌访问 `GET /note-pairs/:id/note` 获得批准时的笔记纯文本快照。每次读取复核配对状态、有效期及笔记是否仍属于创建者且未删除。手机令牌与扫码上传令牌隔离，绝不授予其他笔记、文件或账号权限；到期条件在请求时判断，不能仅依赖 Mongo TTL。
- 公开笔记：`POST /shares` 以 `noteId` 指定本人未删除的笔记，和文件的 `targetId` 二选一；保存创建时快照，支持可选 `maxViews`（`null` 或 1–1,000,000）。`PATCH /shares/:id` 可以调整上限，但不能低于已经成功领取的 `viewCount`，降得过低返回 `409 LIMIT_USED`；文件分享不能设置该字段。`POST /public/shares/:handle/:slug/browse` 对笔记只返回类型与分享标题等元信息，不返回正文也不消耗额度；`POST /public/shares/:handle/:slug/note` 需经分享提取码、到期/撤销及原笔记仍存在的检查后才返回纯文本快照，每成功领取一次正文原子增加 `viewCount`（同一访客刷新再取也计一次），达到上限返回 `429 VIEW_LIMIT`。笔记仅可阅读/复制，不能设置活动封面、文件下载额度、预览关闭或跨站无法生效的“要求登录”（建议使用提取码）；公开二维码仅包含可配置分享 URL。笔记删除后公开访问失效。

### 节点 API 契约

- 所有节点路由要求登录，数据查询和变更始终限定为当前用户；跨用户或不存在的节点统一返回 `404`。
- `GET /nodes` 默认列出根目录（`parentId` 缺省），可传 `parentId` 列出活动文件夹的直接子项；`view=trash` 列出回收站顶层项目，带 `parentId` 时列出该回收站文件夹的直接子项。支持 `offset`（默认 `0`）、`limit`（默认 `50`，最大 `100`）、`sortBy=name|createdAt|updatedAt|size`、`sortOrder=asc|desc`，响应为 `{ items, total, offset, limit }`。
- `POST /nodes/folder` 请求体为 `{ name, parentId? }`；`parentId` 缺省或 `null` 表示根目录。文件夹名称去除首尾空格，长度 1–255，不能包含斜杠、反斜杠或 NUL。
- `PATCH /nodes/:id` 只接受 `name`、`parentId`；缺省字段不变，`parentId: null` 表示移动到根目录。移动目标必须是当前用户的活动文件夹，禁止将文件夹移动到自身或其后代；目前不强制同目录名称唯一。
- `DELETE /nodes/:id` 为软删除；删除文件夹时递归将其子树移入回收站。子节点记录 `deletedRootId` 以关联本次删除根节点。响应包含 `{ deletedCount }`。
- `POST /nodes/:id/restore` 恢复回收站顶层项目；恢复文件夹会一并恢复该次递归删除的整棵子树。子节点须先恢复其所在的回收站根文件夹。响应包含 `{ node, restoredCount }`。本次暂不提供永久删除或清空回收站接口。
- `GET /nodes/:id/url?purpose=preview|download` 要求登录，仅为当前用户未删除、已入库且处于 ready 状态的文件签发 GET 链接；缺省为 preview，不可预览的 MIME 则作为附件下载。返回 `{ url, expiresAt, name, mime, previewable }`，10 分钟有效，响应 `Cache-Control: private, no-store`。通过 `COS_READ_DOMAIN=assets.convenience.top` 配置已绑定此桶的自定义源站域名，签名时将该域名作为 Host；不配置则沿用 COS 默认域名。上传仍使用 COS 原域名。签名链接本身可授权访问，切勿记录、公开或共享缓存；桶始终保持私有读写。
- `GET /nodes/search?q=...` 对当前用户未删除节点的名称做不区分大小写的字面子串匹配（不把搜索词解释为正则表达式），支持 `offset`、`limit`，响应为 `{ items, total, offset, limit }`。
- 节点响应字段为 `id,parentId,type,name,size,mime,status,createdAt,updatedAt,uploadedAt,deletedAt`；不会向客户端暴露内部 `cosKey`。
- `GET /nodes/:id` 验证归属与活动状态，响应 `{node, ancestors}`，其中 `ancestors` 从根级到父目录排列，供深链接恢复路径；无权或已删除返回 404。
- `GET /nodes/:id/location`、`PATCH /nodes/:id/location`（本地实现，待部署）：登录用户只能读取/更新自己的 `ready` 且未删除文件；非法 ID 或非法请求字段返回 `400 INVALID_INPUT`，不存在/他人/文件夹/未就绪/已删除统一 `404 NODE_NOT_FOUND`。GET 返回 `{location:null}` 或 `{location:{latitude,longitude,placeName,source:'exif'|'srt'|'manual'}}`；PATCH 严格接收 JSON `{latitude:number,longitude:number,placeName?:string|null}` 并返回相同结构、`source:'manual'`，手动修改可覆盖自动位置；省略或 `null` 地名会清除原地名，经度范围 −180～180、纬度 −90～90（含 0）、地名最多 60 字且拒绝控制字符。输入与存储均为 WGS-84，未进行 GCJ-02 转换；位置存在节点的独立 `mediaLocation` 字段、仅对当前节点原子写入，不改变 `uploadedAt`，也不出现在普通节点列表、分享或首页汇总响应中；两个接口均 `Cache-Control: private, no-store`。新上传时仅浏览器读取已选 JPEG/JPG 的 EXIF GPS 或同一次文件选择中唯一同名主体（扩展名外部分，不区分大小写）的 MP4/MOV + `.srt`；批次不同、文件重名或缺失配对一律不自动定位。SRT 支持 `[latitude: ...] [longitude: ...]` 和 `GPS(纬度,经度,高度)`（可有空格），只取首个有效字幕帧的 GPS，不使用 `HOME(...)`；仅处理不大于 4 MiB 的 UTF-8/UTF-16 BOM SRT；其他图片格式、内嵌字幕和视频轨迹不解析。解析失败不影响上传，预览页显示“未定位”并可手动补充；不回扫存量素材。客户端来源/坐标不能证明文件内容真实性，后端只做认证、归属、范围及文件格式校验。尚未提供地点名反查或县级点亮；地图点位只读接口已在本地实现、未部署；未来引入 `media_meta`、地理索引与县界数据时需明确迁移及唯一数据源。
- 对象 Key 仅从数据库读取且须位于当前用户的 `originals/` 前缀；HTML、SVG、SRT 等不在内联白名单时强制下载。已签链接到期前仍有效，软删除不能立即撤销；默认 COS 域名对新建桶可能不支持浏览器直接预览。原片签名接口已上线，但仍需登录用户用已上传素材验证真实预览。`purpose=thumbnail` 固定处理为最长边 320px JPEG（源图片不超过 30 MiB），处理参数随 URL 一同签名且默认关闭；上线前需小样本验证私有桶 CI 处理、实际缩图字节、签名 Host 与计费，再设置 `COS_IMAGE_PROCESSING_ENABLED=true`，失败时不回退大原片。

### 分享与展示型活动页 API 契约（本地已实现，未部署）

- 账号 `PATCH /auth/handle {handle}`：公开用户名 3–30 位、全站唯一、保留旧用户名映射且不得被其他用户再次注册；仅修改 `publicHandle`，不改 Mongo `_id`、JWT `sub` 或 COS 路径。保留敏感路径名，公开用户名须以小写字母开头。
- 本人分享管理 `GET /shares`、`POST /shares`、`PATCH /shares/:id`、`DELETE /shares/:id`；创建时传 `targetId`（本人未删除文件或文件夹），并可配置 `slug,title,description,mode=standard|activity,coverNodeId,password,requireLogin,expiresAt,allowPreview,allowDownload,maxDownloads`。更新 `password` 留空/缺省保持原提取码、传 `null` 删除；`expiresAt`、`maxDownloads` 传 `null` 表示无限制。撤销是软失效；自定义路径在同一用户内唯一（含已撤销记录）；改路径后旧路径失效。
- 访客 `POST /public/shares/:handle/:slug/browse` 输入 `{password?,parentId?,offset?}`，输出当前分享元数据、分享根和只读目录分页；`POST /public/shares/:handle/:slug/files/:nodeId/access` 输入 `{password?,purpose:preview|download}`，返回私有 COS 约 60 秒短期签名地址。提取码仅保存 argon2id 哈希、提交时置于请求体，不写 URL；要求登录时使用现有 Cookie 会话。每次签发都复核用户状态、分享期限/撤销、文件归属与当前目录祖先；移动出分享目录即不可再签发。
- `downloadCount` 按**签发下载链接的次数**原子累加；限额针对整个分享而非每个文件。已签发链接在到期前仍可能被重复使用，无法保证实际完成下载次数；浏览器已拿到的预览内容也不能技术性禁止保存。公开页面不显示内部 COS Key、密码哈希，禁用缓存。活动模式是同一分享的封面、标题、介绍和只读作品画廊，不支持访客投稿。
