# 首页设计与 API 契约（供前后端对接）

> `GET /api/v1/home/summary` 已部署到 Lighthouse；React 首页仍待在前端平台发布。以下 JSON 中的数量、地名、素材、旅行仍是虚构格式示例，不代表用户真实数据。

## 1. 首页目标与布局

首页是登录后的个人空间仪表盘，不是第二个文件管理器。重点回答：空间如何、最近添加了什么、足迹进展、如何继续上传/整理。

- **PC**：侧边导航（首页、全部文件、足迹地图、旅行、分享；底部空间用量和账户）；顶栏（搜索、通知、上传）；欢迎区与上传引导；4 张概览卡；足迹预览/云端空间；最近素材/最近旅行。
- **H5**：顶栏压缩为搜索和上传；统计卡两列；地图、空间、素材、旅行纵向排列；底部导航（首页、文件、足迹、旅行、我的），兼顾安全区。
- 约 980px 以下侧边栏缩为图标，700px 以下切 H5 底部导航。设备类别用前端 CSS media query 适配，不用后端 UA 检测，也不作为权限判断。
- 首页卡片仅提供摘要和跳转；文件批量操作、上传队列、真实地图交互、旅行编辑各由独立页面实现。
- 首页预览的示意地图明确标记“示意地图 · 非行政边界”，不代表中国地图/真实县界。真实地图用腾讯地图和核实合规的县界数据。

### 首页模块

| 区块 | 展示内容 | 数据状态 |
|---|---|---|
| 欢迎与导航 | 日期、当前用户昵称、全局导航 | 用户取 `/auth/me` |
| 云空间 | 已用/配额、类型分布 | 上传/计费口径未建立前不显示假数字 |
| 概览卡 | 文件数、点亮县区/省市、旅行数 | 真正无数据才显示 0；接口未就绪显示“准备中” |
| 足迹预览 | 最近位置和地区统计 | 不含全省界，仅为地图页入口/轻量预览 |
| 最近素材 | 4 条最近文件，显示类型/大小/日期/可用缩略图 | 没有素材显示上传引导 |
| 最近旅行 | 2 条最近旅行摘要 | 尚无旅行显示创建/整理提示 |
| 新用户引导 | 上传素材主 CTA，解释图片 EXIF / 大疆 SRT 定位 | 真新用户为空状态 |

## 2. 当前后端接口状态

### 已实现

- `GET /api/v1/auth/me`：当前用户（`id/email/nickname/role/createdAt`）。
- `GET /api/v1/nodes`：当前用户活动目录或回收站的直接子节点，支持分页排序。
- `GET /api/v1/nodes/search?q=...`：只搜索当前用户未删除节点名称。
- `POST /api/v1/nodes/folder`、`PATCH /api/v1/nodes/:id`、`DELETE /api/v1/nodes/:id`、`POST /api/v1/nodes/:id/restore`：文件夹/节点元数据操作。
- `GET /api/v1/nodes/:id`：读取本人未删除节点及其活动目录祖先。
- `GET /api/v1/nodes/:id/url`：为本人已入库的私有文件生成短时签名的预览或下载链接；配置 `COS_READ_DOMAIN` 后链接使用自定义源站域名。
- `POST /api/v1/uploads/credentials`、`POST /api/v1/uploads/complete`：COS 单对象 STS 授权、服务端对象校验及文件节点入库；暂不支持秒传。

### 尚未实现

地图统计、旅行及通知 API 仍未实现。分享管理与公开浏览 API 已部署，但分享域名页面需独立发布。首页汇总与原片私有签名接口已部署，真实用户图片访问仍需本人登录验收。受控 320px 图片缩略图签名已随 API 上线，CI 云端处理待小样本验证且默认关闭；转码尚未接通。方案文档里的其他 API 草案不表示已经提供路由。

**数据边界**：文件节点已可经上传完成接口入库，后端可基于这些已入库节点汇总文件数、用量和最近素材；它们只涵盖通过本系统上传登记的文件，历史上直接存在 COS 但未入库的对象不会自动统计。首页 summary 已上线；节点列表只列单个目录直接子项，不能替代全空间汇总。

## 3. 首页汇总接口（后端已部署）

后端提供登录保护、只读聚合接口；无凭据调用应返回 401：

```http
GET /api/v1/home/summary?recentLimit=4
Cookie: mh_at=<HttpOnly>
```

- `recentLimit`：可选，默认 4，范围 1–8。
- 用户 ID 必须取自已验证会话 `req.user._id`，不接受客户端传入 `userId`。
- 返回 `Cache-Control: private, no-store`；不要共享缓存个人统计或含短期签名的 URL。
- 未登录返回现有格式 `401 {"error":{"code":"UNAUTHORIZED","message":"..."}}`。前端 API client 已带 `credentials: include` 并处理一次刷新重试。
- 模块单独失败时建议用模块级状态返回，不要让一个未实现的地图模块阻塞整个首页。

## 4. 状态、字段与安全语义

各模块使用同一 `status` 枚举：

- `ready`：能力已实现，返回真实统计；
- `empty`：能力已实现，确认当前用户没有数据，计数为 0、列表为 `[]`；
- `not_ready`：底层能力/可信数据源尚未实现。数值返回 `null`、列表返回 `[]`，前端显示准备中，不能伪装为 0；
- `unavailable`：模块本次查询失败，前端局部显示错误和重试。

其它约定：

- `quotaBytes: null` = 不限额，不是 0。未定配额策略时不显示假配额；当前也未启用上传配额扣减。
- `users.usedBytes` 暂不作为事实来源；用量可由已入库活动文件节点汇总。直接存在 COS、但没有对应节点记录的历史对象不在统计内。
- `files.totalFiles` 跨用户所有活动目录计数，仅文件不含文件夹；`recent` 也跨目录，最多 `recentLimit` 条，按 `uploadedAt desc`、再按 ID 排序，不含回收站项目。
- 文件摘要返回 `id/name/type/mime/size/uploadedAt`；缩略图需客户端按需申请、summary 中 `thumbnailUrl: null`，不可返回 `cosKey` 或 COS 凭证。当前云端 CI 缩略图代码默认关闭，需验收后开启。
- `processingStatus` 与 `locationStatus` 当前均返回 `null`，代表对应数据链路尚未建立；不能把上传完成等同于转码/地点已识别。后续接入后再用 `pending|processing|ready|failed` 与 `located|pending|unavailable` 等明确状态。
- `footprint.latestCounty` 无最新记录为 `null`。`countyCount/cityCount/provinceCount` 按当前用户去重统计；无可靠数据时 `null` + `not_ready`，不要返回假 0。
- `trips.recent` 最多 2 条，按 `startAt desc`；底层 `trips` 尚未实现则 `not_ready`。
- 不要把经纬度、完整轨迹或大体量行政区几何塞进首页汇总。全地图页面单独请求地图 API；本首页示意 SVG 不是地图服务。

## 5. 前后端接口对照与开发顺序

| 首页动作/卡片 | 前端调用 | 后端状态/建议 |
|---|---|---|
| 问候、昵称、角色 | `GET /api/v1/auth/me` | 已实现 |
| 全局搜索 | `GET /api/v1/nodes/search?q=...` | 已有但只搜文件名；首页搜索文案应改“搜索文件”，直至地点/旅行检索上线 |
| 全部文件/目录 | `GET /api/v1/nodes` | 已实现直接子项列表 |
| 上传素材按钮 | `POST /api/v1/uploads/credentials` → 浏览器分片直传 COS → `POST /api/v1/uploads/complete` | 前后端上传页已接入；当前新来源 COS 上传 CORS 仍需复核 |
| 概览、最近素材、空间 | `GET /api/v1/home/summary` 的 `storage/files` | 后端已上线；React 首页待在 Makers 发布并登录验收真实数据 |
| 足迹预览 | summary 的 `footprint` | 需要后续 `media_meta/lit_regions` 数据；非完整地图 API |
| 最近旅行 | summary 的 `trips` | 需要后续旅行集合与 CRUD |
| 账号菜单 | `/api/v1/auth/me/logout/change-password` | 已实现 |

推荐后端顺序：

1. 已实现 COS 上传授权、上传完成后端校验、文件节点幂等入库与浏览器上传页；
2. 已上线按用户汇总的 `/home/summary`，`storage/files` 使用已入库节点，`footprint/trips` 返回 `not_ready`；待前端发布及授权用户验收；
3. 落实 EXIF/SRT 和县级判定后再启用足迹统计；
4. 实现旅行模型与 API 后再启用旅行模块。

## 6. 首页原型

- `design/home.html`：PC/H5 同一张页面设计稿；PC 左侧导航、欢迎横幅、4 项指标、足迹/空间、最近素材/旅行；H5 转成顶栏 + 纵向卡片 + 底部导航。本地 React 应用已将 `/` 切到首页，账号页保留 `/settings/account`；尚未将此版本重新部署到 Lighthouse。
- `design/assets/home.css`、`design/assets/home.js`：样式和仅用于原型的“数据视图/新账号空状态”切换；都不是产品业务代码。
- `http://127.0.0.1:4173/home.html`：本地浏览。页面上的示例数据是虚构的；切到“新账号空状态”可查看首次登录引导。
