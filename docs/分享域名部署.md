# 分享域名 share.convenience.top 部署步骤

> 适用：`share.convenience.top/{公开用户名}/{自定义路径}` 公开展示页。
> 前提：已部署含分享接口的 `apps/api`，且已为分享域名单独构建前端（`VITE_APP_BASE=/`）。
> 原则：只在 Lighthouse（111.229.110.233 / lhins-bunuz1ke）上新增独立虚拟主机，不改动现在属于其他应用的 `convenience.top`。

## 0. 现状（只读核对结果）

- 该子域名在多个递归 DNS 下仍无 A 记录，必须先补记录，否则无法签发证书。
- 服务器 nginx 1.24，`/etc/nginx/sites-enabled/movehome` 为 `api.convenience.top` 服务；HTTP 80 已保留 `/.well-known/acme-challenge/` 并指向 `/var/www/html`，其余跳 HTTPS。
- 现有证书是手动放置在 `/etc/nginx/ssl/api.convenience.top.{crt,key}`（非 certbot 管理），`certbot.timer` 处于 active。
- 主站前端在 `/var/www/movehome-app`，通过 `snippets/movehome-web.conf` 以 `/app/` 提供。

## 1. DNS：补 A 记录

在 `convenience.top` 的 DNS 解析控制台添加：

| 主机记录 | 类型 | 记录值 |
|---|---|---|
| `share` | A | `111.229.110.233` |

保存后在本机确认（生效可能需数分钟）：

```bash
dig +short share.convenience.top A   # 应输出 111.229.110.233
```

只有这一步成功后再继续，否则 HTTP-01 校验会失败。

## 2. 签发证书（webroot，不影响现有站点）

SSH 登录服务器后执行：

```bash
sudo certbot certonly --webroot -w /var/www/html \
  -d share.convenience.top \
  --deploy-hook 'cp -L /etc/letsencrypt/live/share.convenience.top/fullchain.pem /etc/nginx/ssl/share.convenience.top.crt && cp -L /etc/letsencrypt/live/share.convenience.top/privkey.pem /etc/nginx/ssl/share.convenience.top.key && chmod 600 /etc/nginx/ssl/share.convenience.top.key && nginx -t && systemctl reload nginx'
```

确认证书文件已就位：

```bash
sudo ls -l /etc/nginx/ssl/share.convenience.top.*
sudo openssl x509 -in /etc/nginx/ssl/share.convenience.top.crt -noout -subject -enddate
```

说明：现有 `api.convenience.top` 证书仍为手动管理，不要删除；`certbot.timer` 会按 `/etc/letsencrypt/renewal/` 自动续新证书，deploy-hook 负责同步到 nginx 目录。

## 3. nginx 独立虚拟主机

新建 `/etc/nginx/sites-available/movehome-share`：

```nginx
# 分享/活动页独立站点：HTTP 仅保留 acme 验证，其余跳 HTTPS
server {
    listen 80;
    server_name share.convenience.top;

    location /.well-known/acme-challenge/ {
        root /var/www/html;
        default_type text/plain;
    }

    location / {
        return 301 https://$host$request_uri;
    }
}

server {
    listen 443 ssl http2;
    server_name share.convenience.top;

    ssl_certificate     /etc/nginx/ssl/share.convenience.top.crt;
    ssl_certificate_key /etc/nginx/ssl/share.convenience.top.key;

    ssl_protocols TLSv1.2 TLSv1.3;
    ssl_prefer_server_ciphers off;
    ssl_session_cache shared:SSL:10m;
    ssl_session_timeout 1d;

    add_header Strict-Transport-Security "max-age=31536000" always;
    add_header X-Content-Type-Options "nosniff" always;
    add_header Referrer-Policy "no-referrer" always;
    add_header X-Frame-Options "SAMEORIGIN" always;

    root /var/www/movehome-share;
    index index.html;
    charset utf-8;

    # 媒体来自私有桶签名 URL：只放行自定义读取域名，防止数据外带
    add_header Content-Security-Policy "default-src 'self'; img-src 'self' data: blob: https://assets.convenience.top; media-src 'self' blob: https://assets.convenience.top; connect-src 'self' https://api.convenience.top; object-src 'none'; base-uri 'none'; frame-ancestors 'self'" always;

    location = /brand-mark.svg { log_not_found off; }
    location /assets/ { expires 7d; add_header Cache-Control "public, max-age=604800"; try_files $uri =404; }
    location = /index.html { add_header Cache-Control "no-store" always; }

    # SPA 深链接回退：/用户名/自定义路径 必须落到 index.html
    location / {
        try_files $uri $uri/ /index.html;
    }
}
```

启用并生效（先备份现配置）：

```bash
sudo cp /etc/nginx/sites-enabled/movehome /opt/movehome/nginx-movehome-before-share.conf
sudo ln -s /etc/nginx/sites-available/movehome-share /etc/nginx/sites-enabled/movehome-share
sudo nginx -t && sudo systemctl reload nginx
```

`nginx -t` 必须通过；失败时先检查证书路径和 `sites-enabled` 是否重复监听。

## 4. 后端允许新来源

在 `/opt/movehome/api.env` 的 `CORS_ORIGINS` 追加 `https://share.convenience.top`（逗号分隔，无空格），然后重启 API 并确认健康检查：

```bash
sudo systemctl restart movehome-api
curl -sS -o /dev/null -w '%{http_code}\n' https://api.convenience.top/health
```

后端对带 Cookie 或非安全方法的请求会校验 `Origin`，不加入来源会被拒为 `BAD_ORIGIN`。修改前先备份 `.env`。

## 5. 发布分享域名前端

同一份前端需要按根路径重新构建（主站仍为 `/app/`）：

```bash
cd apps/web
VITE_APP_BASE=/ npm run build    # 产物在 apps/web/dist
```

将 `dist` **全部内容**上传到 `/var/www/movehome-share`（保留原有目录备份）。分享页默认指向 `https://api.convenience.top`，与第 4 步的 CORS 来源配合。

必须上传 `dist/assets/` 下的**所有**文件，不能只上传 `index.html` 里直接引用的 6 个入口文件：分享页与文件页是按路由懒加载的，运行时才会请求 `PublicSharePage-*.js`、`shares-*.css` 等分片。只上传入口文件会导致线上报 `Unable to preload CSS for .../assets/shares-*.css`（2026-10-28 已踩并修复）。上传后应逐个校验 `/assets/` 下每个文件都返回 200。

### 实际踩到的两个坑（已修）

1. `add_header` 不会跨内部重定向继承。`try_files ... /index.html` 会跳转到 `location = /index.html`，若安全头只写在 `location /` 上，深链接响应会丢失 HSTS/CSP。修复方式：把安全头写在 `location = /index.html` 和 `location = /` 上。
2. 直接访问 `/` 时命中 `location = /index.html`（index 指令），同样需要单独配置，不能只依赖 `location /`。

## 已知限制

- 尚未用真实账号做过端到端验收：请登录 `/app/` → 账号页设置公开用户名 → 在文件页对某个文件/文件夹点「分享」→ 用生成的 `share.convenience.top/{用户名}/{路径}` 链接匿名打开，确认活动页/简洁分享、提取码、预览与下载均正常。“必须登录”的文件分享尚未用真实浏览器账号验收，暂推荐使用提取码。
- 分享域名的前端是独立构建产物，后续主站变更需要分别用 `VITE_APP_BASE=/app/`（主站）和 `VITE_APP_BASE=/`（分享域名）各构建一次并分别发布。

- `share.convenience.top` 与 `api.convenience.top` 是跨源但同站的 HTTPS 子域，`SameSite=Lax` 本身不会禁止来自分享站的请求携带 API 的 host-only Cookie；当前客户端使用 `credentials: include`，API 仍需允许分享站 Origin 和凭据。文件分享的“必须登录”需真实浏览器账号验收，不能仅凭 Cookie 策略断言成功或失败；笔记分享目前在 API 层禁用该选项，建议使用提取码。
- 本文保留分享域名的历史部署步骤；分享域名及文件分享 API 已上线，笔记分享扩展仍只在本地实现，真实账号端到端仍待验收。
